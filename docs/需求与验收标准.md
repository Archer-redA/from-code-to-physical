# 需求与验收标准：自定义宏键盘 / 桌面控制台

> 本文档定义本学期项目的**范围**与**完成标准**。
> 目的：避免「做了一半说不清算不算做完」，也让每一周的进展都能对照检查。

## 1. 一句话描述

做一个桌面上的小型可编程键盘：按下按键 → 电脑收到一个标准键值或组合键；旋钮转动 → 发送音量 / 滚动等操作。按键的功能不写死在固件里，而是通过一个配置文件定义，改配置即改功能。

## 2. 目标用户

我自己。用来替代日常重复的快捷键组合（启动终端、切窗口、IDE 常用操作、静音等）。

## 3. 必做功能（期末必须全部达成）

| 编号 | 功能 | 验收方式 |
|---|---|---|
| F1 | 至少 **6 个独立按键**，每个按键都能被单独识别 | 逐个按下，用键盘测试网页确认每个键的键值互不相同且正确 |
| F2 | 至少有 **1 个旋钮**（旋转 / 按下） | 旋转触发音量增减；按下触发静音 |
| F3 | **免驱识别**：插入电脑后系统自动识别为键盘，无需安装驱动 | 换一台从未接过该设备的电脑，插上即能用 |
| F4 | 按键功能 **由配置文件定义**，不写死在固件里 | 修改配置文件中的映射关系，设备行为随之改变 |
| F5 | 改配置 **不需要重新烧录固件** | 改配置 → 重新连接（或执行一次同步）→ 新映射生效 |
| F6 | 配置错误时有 **兜底行为**，不会导致设备变砖 | 故意写入非法配置，设备仍能被识别、仍能重新配置 |
| F7 | 有一个**上位机配置工具**（命令行或图形界面均可） | 用它生成 / 校验配置文件，并能写入设备 |
| F8 | 整机有**外壳**，不是裸露的电路板 | 装配完成后可以正常放在桌面上使用 |

## 4. 加分功能（时间允许才做，不列入必做）

- 小屏幕：显示当前层 / 按键反馈
- 多层布局：一个物理按键在不同层映射到不同功能
- 按压力度或长按 / 双击识别
- 灯光反馈（按下时亮起）

## 5. 明确不做（非目标）

划清范围，避免项目失控：

- ❌ 不做无线 / 蓝牙连接，只用有线
- ❌ 不做 RGB 灯效矩阵那种复杂灯光系统
- ❌ 不做自定义 PCB 打样，第一版用现成的开发板 + 洞洞板或面包板
- ❌ 不做跨平台驱动，只保证在 Windows 上免驱可用
- ❌ 不做屏幕 GUI 的复杂界面，上位机工具以「能用」为准

## 6. 里程碑

| 周次 | 里程碑 | 通过标准 |
|---|---|---|
| 第 1 周 | 环境与仓库就绪 | 本仓库建立，工具链可验证，本文档定稿 |
| 第 2–3 周 | 硬件到位、主控跑通 | 主控能点灯；单个按键按下能被程序读到 |
| 第 4–5 周 | 固件核心（F1 / F2 / F3） | 插上电脑，按键能打出字，旋钮能调音量 |
| 第 6–7 周 | 可配置（F4 / F5 / F6 / F7） | 改配置文件 → 按键功能跟着变 |
| 第 8–10 周 | 外壳与装配（F8） | 有外壳、能正常放在桌面使用 |
| 第 11–13 周 | 加分项 | 至少完成一项加分功能 |
| 第 14 周 | 收尾 | 全部必做功能通过验收，文档完整，可演示 |

## 7. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 硬件到货慢 | 拖后整个进度 | 第 2 周内下单；等待期先用软件模拟按键扫描逻辑 |
| 免驱识别不成功 | F3 直接不通过 | 优先选用原生支持 HID 的主控方案，避免需要额外驱动的芯片 |
| 焊接 / 外壳做不出来 | F8 不通过 | 先用面包板保证功能达标，外壳作为独立的一步推进 |
| 课程其他任务挤压时间 | 期末赶工 | 里程碑按周检查，落后立刻砍加分项，保必做项 |
