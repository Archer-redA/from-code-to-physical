### 2.1 Git 可用

```console

```

⚠️ **已知问题**：这个版本发布于 2018 年，偏旧。日常能用的影响包括：
不支持 `git switch` / `git restore`（2.23+）、不支持 `init.defaultBranch` 配置项（2.28+）。
目前不影响提交与推送，暂不升级；如果后续协作出现兼容问题，再升级到最新版。

### 2.2 GitHub 身份认证通过（走 SSH）

```console
$ ssh -T git@github.com
Hi Archer-redA! You've successfully authenticated, but GitHub does not provide shell access.
```

这条输出说明 SSH 密钥已被 GitHub 接受，**可以正常推送**。

### 2.3 SSH 走 443 端口的配置

`~/.ssh/config` 内容：

```
Host github.com
    Hostname ssh.github.com
    Port 443
    User git
```

**为什么这样配**：GitHub 的标准 SSH 端口是 22，但在国内网络环境下 22 端口经常被阻断或超时。
GitHub 官方提供了 `ssh.github.com:443` 作为备用入口，把 SSH 流量伪装成 HTTPS 流量出去，
绕开对 22 端口的限制。这是这台机器上必须保留的配置。

| 未安装 `core.quotepath` 相关设置 | git 输出中文文件名时会显示成 `\346\226\207...` 八进制转义，不易读 | 已在本仓库内设置 `core.quotepath = false`（见第 4 节） |

> **换行符说明**：`core.autocrlf = true`，来源是系统级配置 `C:\ProgramData\Git\config`
> （Git for Windows 的默认值）。效果是：工作区里是 CRLF，仓库里存 LF。
> 对本项目这种以 Markdown 文档为主的情况是可接受的默认行为，不做改动，
> 但要知道这个差异存在 —— 以后如果出现「我明明没改这个文件，git 却说它被改了」，
> 大概率就是换行符造成的。

> 说明：本项目的上位机工具优先考虑用 **Node.js** 实现 —— 这台机器上 Node 环境是现成可用的，
> 可以少装一个运行时，属于「用已有的工具解决问题」。

## 4. 本仓库的 git 设置

```bash
# 让 git 直接显示中文文件名，而不是八进制转义
git config core.quotepath false
```

设置前后的区别：

```console
# 设置前
docs/\351\234\200\346\261\202\344\270\216\351\252\214\346\224\266\346\240\207\345\207\206.md

# 设置后
docs/需求与验收标准.md
```

因为本仓库里有中文文件名，这个设置在查看 `git log --stat`、`git status` 时很关键，
否则满屏转义字符根本看不出改了哪个文件。

## 5. 日常工作机制

```bash
# 看当前状态
git status

# 提交一次改动
git add <文件>
git commit -m "docs: 说明这次改了什么"

# 推到远程
git push
```

约定：

- **提交信息**用 `类型: 说明` 的格式，类型包括 `feat` / `fix` / `docs` / `chore` / `refactor`。
- **每次提交只做一件事**，不要把不相关的改动混在一起。
- 仓库保持**公开可见**，方便老师随时查看进度。
